# **Pattern Integration Guide**

## **Purpose**

This document defines how leadership patterns should be integrated into
the manuscript When Others Look to You.

The goal is to increase recognition, recall, and portability without
changing the book's core voice, structure, or intent.

Patterns are diagnostic lenses, not prescriptions. They should clarify
structure, not introduce advice or techniques.

## **Core Principles**

### **1. Do Not Rewrite the Book**

Patterns are additive, not transformative.

- Do not restructure chapters

- Do not change arguments

- Do not introduce new concepts

- Only name and clarify patterns already present

### **2. Preserve the Author's Voice**

The book is:

- Plainspoken

- Structural

- Non-prescriptive

- Observational, not instructional

Pattern insertion must not:

- Sound like management advice

- Introduce slogans or motivational tone

- Break narrative flow

### **3. Patterns Are Recognition Devices**

Each pattern should help the reader think:

> "I've seen this before."

Not:

> "I should do this."

### **4. Patterns Are Optional, Not Required**

Not every chapter needs a pattern.

- Patterns should appear only where they are clearly present and add
  recognition value

- Many sections should have no pattern at all

- Absence of patterns is preferred over weak or forced insertion

A good rule:

If removing the pattern does not reduce clarity or recognition, it
should not be included.

Patterns are used sparingly to highlight the most important structural
moments.

## **Insertion Rules**

### **Rule 1 — Insert Only Where Already Present**

Patterns should be inserted where:

- The concept is already explained

- The dynamic is already visible

- The reader could recognize the pattern without extra explanation

Do not force patterns into weak or unrelated sections.

### **Rule 2 — Place Immediately After Explanation**

Pattern blocks should appear:

- After a paragraph or vignette that demonstrates the concept

- Before moving on to the next idea

Never before the concept is introduced.

### **Rule 3 — Use Minimal Formatting**

Pattern blocks should be short and visually distinct, but not
disruptive.

Format:

::: {custom-style="Pattern Block"}
**Pattern - \[Pattern Name\]**

\[1-2 sentence structural description\]
:::

Example:

::: {custom-style="Pattern Block"}
**Pattern - We Own the Outcome**

When decision-makers stay connected to consequences, accountability
stays visible; when that connection breaks, costs and harm drift out of
view.
:::

### **Rule 4 — Keep It Short**

Each pattern block should be:

- 1-2 sentences

- Maximum 3 lines

- No bullets

- No extended explanation

The appendix holds the full version.

### **Rule 5 — No Redundancy**

Each pattern should appear:

- Once in its primary location (required)

- At most once more in a secondary location (optional)

Patterns should not be repeated across multiple weak contexts.

If a pattern appears more than twice, it is likely overused.

Note: this cap applies to **pattern blocks**. Inline bolded anchors are
governed by the Inline Pattern Anchors section and should remain sparse.

### **Rule 6 — Maintain Flow**

The paragraph before and after the pattern should read naturally if the
pattern block is removed.

Patterns are insertions, not structural dependencies.

### **Rule 7 — Each Pattern Has a Primary Location**

Each pattern must have one primary chapter where it appears in its
strongest, most undeniable form.

- The primary location is where the pattern is most clearly demonstrated

- This is the preferred and often only placement

Secondary placement is optional and should only occur if:

- The pattern is equally strong in that location

- It adds clarity, not redundancy

Avoid placing patterns in multiple weak contexts.

### **Rule 8 — No Pattern Stacking**

Never place multiple pattern blocks adjacent to each other.

- Only one pattern may appear at a given insertion point

- If multiple patterns seem applicable, choose the strongest one

- Prefer omission over stacking

Stacking reduces clarity and weakens pattern recognition.

## **Pattern Selection Rule**

When considering inserting a pattern:

1.  Identify all candidate patterns for the section

2.  Select the single strongest pattern

3.  Discard the rest

If no pattern is clearly dominant, do not insert one.

## **Inline Pattern Anchors (Bolded Mentions)**

Use inline anchors to reinforce pattern recall inside normal prose.

Inline anchors are not pattern blocks. They are short in-sentence uses of
the canonical pattern names in bold:

- `**Attention Comes Into Focus**`
- `**Your Example Becomes the Rule**`
- `**The One We Default To**`
- `**Bring Bad News**`
- `**We Change Course**`
- `**We Own the Outcome**`
- `**No One Pushes Back**`
- `**Feedback Gap**`
- `**Exceptions Are Forever**`
- `**Copy What Works Here**`

### **Inline Anchor Rules**

1. **Sequence rule (required):** do not use a pattern name inline before
   that pattern has been introduced in a pattern block earlier in the
   book.
2. **Use canonical spelling exactly:** same capitalization, apostrophe
   style, and wording as the canonical list.
3. **Keep anchors sparse:** usually 0-2 inline anchors per chapter.
4. **No stacked anchors:** do not place multiple bolded pattern names in
   the same sentence.
5. **No label format inline:** do not write `Pattern - ...` in body prose.
   Use only the bolded name.
6. **Flow first:** the sentence must read naturally if the bolding is
   removed.

### **Introduction Sequence (for Inline Eligibility)**

Patterns become eligible for inline use only after these introduction
chapters:

- After **Chapter 1**:
  - Attention Comes Into Focus
  - Your Example Becomes the Rule
  - The One We Default To
- After **Chapter 3**:
  - Bring Bad News
  - Feedback Gap
- After **Chapter 4**:
  - We Own the Outcome
- After **Chapter 5**:
  - We Change Course
- After **Chapter 6**:
  - No One Pushes Back
- After **Chapter 7**:
  - Copy What Works Here
- After **Chapter 9**:
  - Exceptions Are Forever

### **Inline Syntax Pattern**

Preferred form:

- "...this is where **We Own the Outcome** breaks down."
- "...the group drifts toward **No One Pushes Back**."
- "...what looks stable can mask **Feedback Gap**."

### **Grammar Rule for Inline Anchors**

Treat each pattern name as a fixed title and insert it where a noun phrase
fits naturally in the sentence.

- Use with a determiner when needed: "the pattern **We Own the Outcome**,"
  "a drift toward **No One Pushes Back**."
- Keep subject-verb agreement with the surrounding sentence:
  "**Feedback Gap** is visible here" (not "are visible").
- Keep tense and preposition logic in the host sentence:
  "drifts toward **No One Pushes Back**," "slides into
  **Exceptions Are Forever**," "room for **Bring Bad News**."
- If the sentence becomes awkward, rewrite the sentence; do not bend the
  pattern name.

Good:

- "In this section, **We Own the Outcome** is hard to find."
- "Over time, the group drifts toward **No One Pushes Back**."
- "What looks stable can mask **Feedback Gap**."

Avoid:

- "This is **We Own the Outcome**."
- "They are **No One Pushes Back**."
- "The group is in **Bring Bad News**."

Avoid:

- "Pattern - We Own the Outcome"
- "this is an example of We Own the Outcome pattern dynamics occurring..."

## **Opportunity Map for Inline Anchors (Before Manuscript Edits)**

This map identifies strong candidate places to add bolded inline anchors

  (**Your Example Becomes the Rule**).
- In "What Erosion Looks Like," where repetition hardens authority
  (**The One We Default To**).

### **Chapter 3 — Why We Misjudge Leaders**

Strong opportunities:

- In "How Harm Gets Displaced," where costs move downward/outward and

  short-term narrative at others' expense.

### **Chapter 5 — Effectiveness and Its Illusions**

  Course**).

### **Chapter 6 — Legitimacy Over Time**

### **Chapter 8 — Scale and Drift**

Eligible patterns: Feedback Gap; No One Pushes Back; also **Copy What Works

  local revision (**Copy What Works Here**).

- After the four-state list, where formal routing concentrates who counts as
  the real escalation point (**The One We Default To**).

  enough force (**Feedback Gap**).

  grows (**No One Pushes Back**).

### **Chapter 9 — Tradeoffs Under Pressure**

Strong opportunities:

- In "Boundary Conditions," at the transition from temporary exception to
  default practice (**Exceptions Are Forever**).
- In post-vignette commentary where emergency logic becomes baseline
  governance.

### **Chapter 10 and Epilogue**

Eligible patterns: all patterns.

Strong opportunities:

- In "Two Trajectories" and "When the Baseline Has Already Shifted," where
  transfer, insulation, and delayed feedback converge
  (**Feedback Gap**, **No One Pushes Back**).
- In epilogue sections on emergency permissions and damage containment
  (**Exceptions Are Forever**, **We Own the Outcome**).

### **Bridges (Light Use Only)**

Use at most one inline anchor per bridge, and only when it improves
recall without sounding repetitive.

## **Manuscript vocabulary alignment**

When inserting or revising pattern blocks in *When Others Look to You*, keep
surrounding prose aligned with the book’s enforced plain-language and echo
rules—not only pattern naming. After substantive edits, cross-check
`docs/editorial-vocabulary.md` (look vs follow, harm vignette domain,
renewal/erosion labels in Chapter 2, Part III definition echo limits) so
pattern callouts do not reintroduce deprecated jargon or duplicate the full
four-state model where the manuscript says not to.

## **Anti-Patterns (What to Avoid)**

### **❌ Do Not Explain the Pattern at Length**

Bad:

"Pattern - We Own the Outcome: This occurs when..."

Good:

"Pattern - We Own the Outcome"

Short. Recognizable. Move on.

### **❌ Do Not Stack Patterns**

Never place multiple patterns back-to-back.

### **❌ Do Not Introduce New Terminology**

Only use the canonical pattern names.

### **❌ Do Not Change Tone**

Avoid:

- "Leaders should..."

- "Best practice..."

- "You must..."

## **Appendix Relationship**

The appendix contains:

- Full pattern definitions

- Context, forces, and effects

The main text contains:

- Recognition triggers only

The two should complement, not duplicate.

## **Cursor Usage Guidance**

When prompting Cursor, use instructions like:

- "Insert the pattern 'We Own the Outcome' after this paragraph using the
  guide"

- "Add a pattern block here following pattern-integration-guide.md
  rules"

- "Do not rewrite text, only insert pattern block"

## **Chapter-Level Quality Check**

After inserting patterns into a chapter, verify:

- No pattern stacking occurs

- Each pattern appears in a strong, relevant context

- The chapter reads naturally without the pattern blocks

- The number of pattern insertions is minimal (often 0-2 per chapter)

It is acceptable - and expected - for some chapters to contain no
patterns.

If any insertion feels optional, remove it.

## **Final Check**

After full integration, verify:

- The book still reads cleanly without the appendix

- Patterns feel natural, not forced

- Each pattern has a clear primary location

- No pattern is overused

- Total pattern insertions remain limited and context-earned (often
  fewer than ~14-18 total, given the expanded pattern set)

## **Summary**

Patterns are:

- Names for recurring structural dynamics

- Inserted lightly into the text

- Fully defined in the appendix

They should make the book more:

- Memorable

- Recognizable

- Portable

Without making it more complicated.
