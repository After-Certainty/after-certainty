### Window reconciliation (review item 1)

**Bug:** The first manual collection passed Denver inclusive `until=YYYY-MM-DD` into Vercel. `visits/count` often advanced a day while `*/aggregate` resolved to that day’s `T01:00`, so events/country/referrer slices missed most of the inclusive end day (e.g. current-week `chapter_open` 5 vs regenerable 6; SG 72 vs 93).

**Fix:** Re-run via [`scripts/collect-nov2026-evaluation-pack.sh`](../../scripts/collect-nov2026-evaluation-pack.sh) using `vercel_iso_request_bounds` (exclusive until = day-after at `T00:00:00.000Z`). Enforce with `python3 tools/reader_analytics_parity.py validate-evidence-pack --pack-dir … --since … --until …` (allows documented `by=day` until = exclusive-end + 1 day at T00 without weakening the visits/events rule).

**Result:** Current-week visits/events/country/referrer now match regenerable `raw/` (`chapter_open` 6, SG 93, empty-referrer 142).

## 5. Discovery and traffic-quality findings

### Discovery

- **Referrers (Vercel, full):** empty hostname ~1,796 visitors; `google.com` ~38; other search hosts negligible. Meaningful external referral beyond Google is thin.
- **Channels (GA4, full):** Direct 47 sessions; Organic Search 14; AI Assistant 2.
- **Pages:** Research/source paths and `/explore` dominate top rows; specific chapters (e.g. *No Time to Think*, *Everyone Knows Love*) appear in the truncated path list. Path-prefix family filters are unsupported — treat path tables as partial.
- **GSC (retained, not re-queried here):** remains the authority for search queries, impressions, and rankings. Retiring GA4 does not remove that discovery surface.

### Traffic quality (heuristic — not bot proof)

| Signal (full window, Vercel) | Observation |
|------------------------------|-------------|
| Country | **SG ~1,643 / 1,860 visitors (~88%)**; US ~100 |
| Device | Desktop ~1,767 visitors; mobile ~37 |
| Referrer | Empty hostname dominates |
| Page families | Heavy `/explore` + research/source URLs in top paths |
| Custom reader engagement | Tiny vs pageviews (`chapter_open` 33 vs 3,069 pageviews) |
| Change over time | Prior-7 still SG-heavy (217 SG visitors); current-7 SG share lower in absolute terms (72) but still plurality |

**GA4 geography (consent-gated)** is US-led (53 US sessions vs 4 Singapore) — evidence that ungated visitor totals and consent-scoped sessions describe different populations.

**Interpretation:** Headline Vercel visitors/pageviews are not a clean “human readership” KPI. Prefer custom reader events, non-empty referrers, and GSC for editorial judgment. Do **not** silently exclude SG traffic from reports; do **not** treat the heuristic as confirmed automation.

## 8. Final recommendation

### `retire_ga4` (restored after PR #770 verification; supersedes `corrective_pr_required`)

Retirement direction is sound for chapter/corpus/audio/download measurement. The two review blockers are **closed in production**:

1. **Path-start** — #770 queue stub; post-deploy Vercel `reading_path_started` **count 3 / visitors 2** with question + trail `path_id` dims.  
2. **On-site search** — #770 `site_search` dual-write; post-deploy Vercel **count 2 / visitors 1** with bucket props only (no raw query text).

**Not** `keep_parallel_longer`: the observation window and corrective verification are enough.  
**Not** `corrective_pr_required` anymore: instrumentation gaps that blocked retirement are verified closed.

Owner approval is still required before PR 4. Consent/privacy review remains part of PR 4 scope.

### Path-start investigation → fix → verify

| Check | Pre-corrective | Post-#770 |
|-------|----------------|-----------|
| Call sites | `QuestionPathAnalytics` / `TrailPathAnalytics` → `trackReaderEvent({ name: "reading_path_started", … })` | unchanged |
| Root cause | `track()` does not call `initQueue`; mount effects could run before `<Analytics />` | `ensureVercelAnalyticsQueue()` before every custom event |
| GA4 by date (full window) | 2026-10-17:1, 2026-10-23:3, 2026-10-24:1 | historical context only |
| Vercel filtered aggregate | empty `data: []` | **count 3 / visitors 2** (`post-corrective/events_reading_path_started.json`) |
| Dims | — | question `love-hard-to-explain`; trails `accountability-and-enduring-authority`, `judgment-before-certainty` |

Verification used shell Playwright (not computerUse) with Accept → hard-load question/trail/search, then PADE `vercel.analytics.read`. Default Playwright `navigator.webdriver` kept the insights collector from replacing `window.va`; stealth init was required for `/_vercel/insights/event` POSTs (events still queue correctly either way).

### On-site search (review item 3) — closed

GSC still answers only external Google queries. In-site search is now dual-written as Vercel `site_search` with privacy-safe buckets (`surface`, `has_results`, `result_count_bucket`, `query_length_bucket`)—**never** raw query text. Keep GA `search_query` until retirement.

Post-deploy: client POSTs observed; PADE `site_search` **count 2 / visitors 1** (`post-corrective/`).
